# AI Document Intelligence

A local document question-answering application built with **Retrieval-Augmented Generation (RAG)**. Upload PDF, DOCX, or TXT documents, ask questions in a Streamlit interface, and receive answers generated by a local Ollama model with retrieved source references.

## Features

- Extracts text and source metadata from PDF, DOCX, and UTF-8 TXT documents.
- Splits text into overlapping chunks for retrieval.
- Generates normalized embeddings with `sentence-transformers/all-MiniLM-L6-v2`.
- Stores and searches document chunks using FAISS inner-product similarity.
- Generates grounded answers using Ollama (`qwen2.5:0.5b`).
- Provides FastAPI endpoints for document upload and question answering.
- Includes a Streamlit interface for uploads, questions, and source inspection.
- Persists the FAISS index across restarts and uses a temporary-directory/backup approach when saving updates.
- Validates document formats and enforces a configurable upload size limit (10 MB by default).
- Runs FastAPI and Streamlit in separate Docker Compose services.

## Architecture

```text
PDF / DOCX / TXT
       |

       v
Document loader and validation
       |
       v
Text chunking -> SentenceTransformer embeddings
       |                         |
       +-------------------------v
                         FAISS vector index
                                |
User question -> Query embedding -> Top-k retrieval
                                |
                                v
                        Context + question
                                |
                                v
                      Ollama (local Qwen2.5)
                                |
                                v
                     Answer + source references

Streamlit UI <---- HTTP ----> FastAPI backend
```

## Prerequisites

- Docker Desktop with Linux containers enabled.
- Ollama installed and running on the host computer.
- Local Ollama model downloaded:

```powershell
ollama pull qwen2.5:0.5b
```

- An existing FAISS index in `data/faiss_index/` containing `index.faiss` and `chunks.json`. **The current backend loads an existing index on startup; it does not initialize an empty index automatically.** If starting from scratch, create and save an index using the project's ingestion/chunking/embedding components before launching the API.

## Run with Docker Compose

1. Open a terminal in the project root.
2. Create `.env.docker` with the following values (adjust as needed):

```dotenv
API_HOST=0.0.0.0
API_PORT=8000
OLLAMA_BASE_URL=http://host.docker.internal:11434
OLLAMA_MODEL=qwen2.5:0.5b
EMBEDDING_MODEL=sentence-transformers/all-MiniLM-L6-v2
DEFAULT_TOP_K=3
MAX_UPLOAD_SIZE_MB=10
BACKEND_URL=http://backend:8000
```

3. Ensure Ollama accepts requests from Docker. On Windows, `host.docker.internal` resolves to the host, but Ollama may need its listening address configured to accept connections beyond `127.0.0.1` (for example, via `OLLAMA_HOST=0.0.0.0:11434`). Configure this only for trusted local networks and avoid exposing Ollama publicly.
4. Start the services:

```powershell
docker compose up --build -d
docker compose ps
```

5. Open the interfaces:
   - Streamlit: http://localhost:8503
   - API health check: http://localhost:8000/health
   - FastAPI interactive documentation: http://localhost:8000/docs

> The provided Compose configuration publishes Streamlit on host port **8503** and container port **8501**. If you change the port mapping, update the URL above. FAISS data is bind-mounted from `./data/faiss_index`.

To stop the services:

```powershell
docker compose down
```

## Run Locally (Without Docker)

Use Python 3.11 and install the project dependencies:

```powershell
python -m pip install -r requirements.txt
```

Copy `.env.example` to `.env`, set `OLLAMA_BASE_URL=http://127.0.0.1:11434` and `BACKEND_URL=http://127.0.0.1:8000`, and ensure the saved FAISS index exists. Run these commands in separate terminals:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```powershell
python -m streamlit run frontend/streamlit_app.py
```

## API Overview

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/` | Application information |
| GET | `/health` | Basic API health response |
| POST | `/upload` | Upload and index a PDF, DOCX, or TXT file |
| POST | `/ask` | Ask a question using retrieved document context |

Example question request:

```json
{
  "question": "Who manages Project Atlas?",
  "top_k": 3
}
```

`/ask` returns the question, generated answer, and retrieved sources with metadata and similarity scores.

## Testing and Evaluation

Run automated tests:

```powershell
python -m pytest tests/ -v
```

**Verified during local development:** 29 of 29 automated tests passed. The suite covers API behavior, document ingestion/validation, chunking, FAISS search, persistence, and selected save-failure scenarios. API tests use mocked services, so they do not by themselves prove live Ollama availability.

For a running local API, run the small RAG evaluation script:

```powershell
python evaluation/evaluate_rag.py
```

**Observed on a three-question test set:** retrieval Hit@3 = 3/3, answer checks = 3/3, and average latency approximately 0.775 seconds. These checks use a small known-answer set and simple answer matching; they are **not** a general accuracy benchmark.

**Live Docker smoke test:** Asking *“Who manages Project Atlas?”* returned *“Project Atlas is managed by David Wilson.”* with `atlas_test.txt` as the first retrieved source.

## Known Limitations

- The backend currently expects a saved FAISS index at startup; first-time index initialization is not automated.
- Index updates rebuild the in-memory FAISS index and are serialized only within one API process. Multiple backend workers or concurrent writers are not supported.
- The save/backup mechanism handles tested failures but does not guarantee crash-safe recovery after abrupt process or host shutdown.
- Duplicate document detection is not implemented; uploading the same content again can create duplicate chunks.
- DOCX ZIP safety checks and document validation are not a complete defense against all malformed or resource-exhausting files.
- Scanned PDFs without extractable text require OCR, which is not included.
- The local 0.5B language model may give incomplete or incorrect answers; retrieved sources should be checked.
- No user authentication, role-based access, or public-internet deployment hardening is provided. Intended for local demonstrations and portfolio use.
